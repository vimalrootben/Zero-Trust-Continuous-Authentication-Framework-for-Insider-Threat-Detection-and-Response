MODULE: M-COMM — Communication Protocol Specification
--------------------------------------------------------------------------------
PURPOSE: Define the exact wire format so Manager and Agent modules built in
separate sessions are still compatible.

TRANSPORT: HTTPS (TLS 1.2+) with mutual TLS. Each agent has a unique client
certificate issued at enrollment. Manager verifies the client cert chain
against its own CA on every request, in addition to any JWT service token.

ENDPOINTS (Agent -> Manager, agent-initiated only, never the reverse for
data collection):
  POST /agent/register            -> enrollment
  POST /agent/heartbeat           -> periodic liveness + resource stats
  POST /agent/telemetry           -> batched telemetry push
  POST /agent/commands/ack        -> acknowledge receipt of a command
  POST /agent/commands/result     -> report execution result
  GET  /agent/commands/pending    -> poll fallback if WebSocket unavailable
  WS   /agent/ws                  -> persistent channel for low-latency
                                      command push (preferred over polling)

REGISTRATION PAYLOAD:
{
  "enrollment_token": "string",
  "hostname": "string",
  "os_version": "string",
  "agent_version": "string",
  "hardware_fingerprint": "string",   -- sha256 of stable HW identifiers
  "public_key_csr": "base64 PEM CSR"  -- agent generates keypair locally,
                                          manager's CA signs and returns cert
}
REGISTRATION RESPONSE:
{
  "agent_id": "uuid",
  "signed_certificate": "base64 PEM",
  "ca_certificate": "base64 PEM",
  "initial_policy_group": "uuid",
  "heartbeat_interval_seconds": 30
}

HEARTBEAT PAYLOAD:
{ "agent_id": "uuid", "timestamp": "ISO8601", "cpu_usage": float,
  "memory_usage": float, "disk_usage": float, "status": "active" }

TELEMETRY BATCH PAYLOAD:
{ "agent_id": "uuid", "batch_id": "uuid",
  "events": [ { "collector_type": "process", "event_type": "process_start",
                "timestamp": "ISO8601", "data": { ... collector-specific ... } } ] }
Response: { "accepted": int, "rejected": int, "batch_id": "uuid" }

SIGNED COMMAND OBJECT (Manager -> Agent, via WebSocket push or poll):
{
  "command_id": "uuid",
  "command_type": "LOGOFF_USER | KILL_PROCESS | DISABLE_NETWORK |
                    ENABLE_NETWORK | DISABLE_ADAPTER | ENABLE_ADAPTER |
                    LOCK_WORKSTATION | ADD_FIREWALL_RULE |
                    REMOVE_FIREWALL_RULE | RESTRICT_RESOURCE |
                    QUARANTINE_FILE | RESTORE_FILE | CREATE_SCHEDULED_TASK |
                    DELETE_SCHEDULED_TASK | STOP_SERVICE | START_SERVICE",
  "agent_id": "uuid",
  "policy_id": "uuid|null",
  "issued_by": "uuid|null",
  "params": { ...command-specific... },
  "issued_at": "ISO8601",
  "expires_at": "ISO8601",
  "signature": "base64 HMAC-SHA256 or RSA signature over the canonical
                JSON of all fields above except signature itself"
}
Agent MUST: verify signature using the manager's known public key,
verify `expires_at` has not passed (replay protection), verify
`agent_id` matches itself, THEN execute, THEN POST the result to
/agent/commands/result:
{ "command_id": "uuid", "status": "success|failed",
  "output": "string", "error": "string|null", "executed_at": "ISO8601" }

REPLAY / TAMPER PROTECTION: every command carries a strictly increasing
`nonce` OR is single-use (agent keeps a local set of executed command_ids
for the last 24h and rejects duplicates). Clock skew tolerance: 60s.

OFFLINE BEHAVIOR: if the agent cannot reach the manager, telemetry events
queue in the local SQLite offline queue (see A5). Heartbeats simply fail
silently and retry with exponential backoff (base 5s, cap 5min, jitter).
On reconnect, agent flushes the offline queue in batches of N (configurable,
default 100) and logs the sync in `offline_sync_log` (server-side, created
from the batch's `batch_id`).

--------------------------------------------------------------------------------
MODULE M1: AUTHENTICATION
--------------------------------------------------------------------------------
PURPOSE: Handle user identity — registration (admin-created, no public
self-signup for an EDR console), login, logout, token refresh, password
management, optional TOTP MFA, account lockout.

RESPONSIBILITIES:
- Hash and verify passwords (argon2).
- Issue short-lived JWT access tokens (15 min) and long-lived opaque
  refresh tokens (7 days, rotated on each use, stored hashed in `sessions`).
- Enforce account lockout after N failed attempts (default 5, 15 min lock).
- Optional TOTP-based MFA (pyotp), enforced per-user via `mfa_enabled`.
- Emit audit_log entries for login success/failure/logout/lockout.

DEPENDENCIES: database (users, sessions tables), auth/rbac.py (to embed
role/permissions into the JWT claims), audit log writer.

DATA MODELS (Pydantic schemas, api/schemas/auth.py):
- LoginRequest { username: str, password: str, totp_code: str | None }
- LoginResponse { access_token: str, refresh_token: str, token_type: "bearer",
                   expires_in: int, user: UserPublic }
- RefreshRequest { refresh_token: str }
- RefreshResponse { access_token: str, refresh_token: str, expires_in: int }
- ChangePasswordRequest { old_password: str, new_password: str }
- UserPublic { id: UUID, username: str, email: str, role: str,
                department: str | None, mfa_enabled: bool }

CLASSES & METHODS:

class PasswordHandler:
    def hash_password(self, plain: str) -> str: ...
        """Hash using argon2id. Raises WeakPasswordError if policy fails
        (min 12 chars, upper+lower+digit+symbol)."""
    def verify_password(self, plain: str, hashed: str) -> bool: ...

class JWTHandler:
    def __init__(self, secret_or_private_key: str, algorithm: str = "RS256",
                 access_ttl_minutes: int = 15, refresh_ttl_days: int = 7): ...
    def create_access_token(self, user_id: UUID, role: str,
                             permissions: list[str]) -> str: ...
    def create_refresh_token(self) -> tuple[str, str]:
        """Returns (raw_token, sha256_hash_to_store)."""
    def decode_access_token(self, token: str) -> TokenPayload:
        """Raises ExpiredTokenError, InvalidTokenError."""
    def verify_refresh_token(self, raw_token: str, stored_hash: str) -> bool: ...

class AuthService:
    def __init__(self, db_session, password_handler: PasswordHandler,
                 jwt_handler: JWTHandler, audit_logger): ...
    async def login(self, username: str, password: str,
                     totp_code: str | None, ip: str, user_agent: str
                     ) -> LoginResponse:
        """
        Flow: fetch user -> check is_active -> check locked_until ->
        verify password (on fail: increment failed_login_attempts, lock
        if threshold hit, audit log, raise InvalidCredentialsError) ->
        if mfa_enabled: verify totp_code (raise MFARequiredError /
        InvalidMFACodeError) -> reset failed_login_attempts -> create
        session row -> issue tokens -> audit log success -> return.
        """
    async def refresh(self, raw_refresh_token: str) -> RefreshResponse:
        """Look up session by hash, verify not revoked/expired, rotate:
        revoke old session, create new session + new tokens (refresh
        token rotation prevents replay). Raise InvalidRefreshTokenError
        if not found/revoked/expired."""
    async def logout(self, raw_refresh_token: str) -> None:
        """Revoke the session row."""
    async def change_password(self, user_id: UUID, old_password: str,
                               new_password: str) -> None: ...
    async def enable_mfa(self, user_id: UUID) -> str:
        """Generates TOTP secret, stores it, returns provisioning URI
        for QR code display."""
    async def confirm_mfa(self, user_id: UUID, totp_code: str) -> None:
        """Verifies first code before flipping mfa_enabled = True."""

EXCEPTIONS (exceptions.py):

MODULE M7: RISK ENGINE
--------------------------------------------------------------------------------
PURPOSE: Maintain a continuously updated "trust score" per agent (0-100,
where higher = riskier, or invert if you prefer — BE CONSISTENT, this spec
uses higher = riskier), driven by rule matches, with decay over time for
good behavior (Zero Trust "continuous" scoring, not a one-time check).

RESPONSIBILITIES:
- On every rule match (from M8), apply a score delta.
- Periodically decay scores toward baseline for agents with no recent
  negative events (rewards good behavior, prevents permanent flagging).
- Expose current score + history per agent.
- Trigger Policy Engine evaluation whenever a score changes (M11).

SCORING TABLE (seed data — starting point, extend via rules, not hardcoding
in the engine itself — the engine reads deltas from `rules.condition_json`
or a dedicated `score_impact` field on the rule, NOT from if/else in code):
  USB device inserted:              +10
  PowerShell execution (unsigned):  +20
  Unknown/unsigned binary executed: +15
  Credential dumping tool detected: +40
  Failed login threshold exceeded:  +15
  Off-hours access to sensitive resource: +20
  Known-bad IOC match (threat intel): +35
  Lateral movement pattern detected: +30
  Baseline decay (no negative event in 24h): -5 (floor at 0)

CLASSES & METHODS:

MODULE M11: POLICY ENGINE
--------------------------------------------------------------------------------
PURPOSE: Decide WHAT response actions to take based on current risk score
+ agent attributes, decoupled from the Rule Engine (rules detect, policies
decide response — this separation is what makes the system "not hardcoded
if/else").

POLICY DEFINITION FORMAT (`policies.condition_json` / `actions_json`):
condition_json example:
{ "all": [ { "field": "risk_score", "op": "gt", "value": 80 },
            { "field": "agent.department", "op": "ne", "value": "IT" } ] }
actions_json example (ordered — executed in sequence, each logged):
[ { "action": "LOGOFF_USER", "params": {} },
  { "action": "DISABLE_NETWORK", "params": {} },
  { "action": "NOTIFY_SOC", "params": { "channel": "dashboard" } },
  { "action": "CREATE_INCIDENT", "params": { "severity": "high" } } ]

CLASSES & METHODS:

class PolicyEvaluator:
    def evaluate(self, condition: dict, context: dict) -> bool:
        """Reuses the same ConditionEvaluator engine as M8 (share the
        library — don't duplicate the operator logic) against a context
        dict of { risk_score, agent: {...}, recent_alerts: [...] }."""

class PolicyEngine:
    def __init__(self, db_session, evaluator: PolicyEvaluator,
                  command_dispatcher, alert_service, incident_service): ...
    async def evaluate(self, agent_id: UUID) -> list[PolicyActionResult]:
        """Loads enabled policies ordered by priority (ascending = higher
        priority evaluated first), builds context, evaluates each; on
        match, executes actions_json in order via
        _execute_action(); supports a `stop_on_match` flag per policy
        (default True) to prevent cascading conflicting policies."""
    async def _execute_action(self, agent_id: UUID, action: str,
                                params: dict, policy_id: UUID
                                ) -> PolicyActionResult:
        """Dispatch table mapping action string -> handler:
        LOGOFF_USER/KILL_PROCESS/DISABLE_NETWORK/etc. -> builds a
        SignedCommand and calls command_dispatcher.dispatch();
        NOTIFY_SOC -> pushes a dashboard notification via WebSocket;
        CREATE_INCIDENT -> incident_service.create_from_agent(agent_id).
        Every action attempt is logged with success/failure regardless of
        whether the downstream command itself later succeeds/fails
        (that's tracked separately via commands.status)."""

API ENDPOINTS:
GET/POST/PUT/DELETE /api/v1/policies       (permission: policies:read/write)
GET/POST /api/v1/policy-groups
POST /api/v1/policies/{id}/test            (dry-run against a given agent_id,

                                              actions WITHOUT executing —

LOGGING: policy.evaluated (agent_id, matched_policy_ids), policy.action.executed,
policy.action.failed

[ ] Policy evaluation reuses M8's ConditionEvaluator (no duplicated logic)

MODULE A6-A12: COLLECTORS
--------------------------------------------------------------------------------
SHARED INTERFACE (base_collector.py — every collector implements this):

class BaseCollector(ABC):
    def __init__(self, event_sink: Callable[[TelemetryEventDTO], None]): ...
        """event_sink is called for every collected event — wired to
        either the offline queue (if disconnected) or the telemetry
        sender's batching buffer (if connected); the collector itself
        doesn't know or care about connectivity state."""
    @abstractmethod
    def start(self) -> None:
        """Begin monitoring (spawn a thread/async task/WMI subscription
        as appropriate to the collector type)."""
    @abstractmethod
    def stop(self) -> None:
        """Clean shutdown — release WMI subscriptions, stop threads."""
    @abstractmethod
    def collector_type(self) -> str: ...

--- A6: PROCESS COLLECTOR (collectors/process_collector.py) ---
MECHANISM: WMI event subscription (Win32_ProcessStartTrace /
Win32_ProcessStopTrace via `wmi` or `pywin32`) — event-driven, NOT polling
(polling misses short-lived processes, a common evasion technique).
COLLECTED DATA per process_start event:
  process_name, pid, ppid, parent_process_name, command_line,
  executable_path, executable_sha256 (hash on first sight, cache hash by
  path+mtime to avoid re-hashing unchanged files), signed (bool, via
  Authenticode check — subprocess call to `signtool verify` or use
  `win32api.GetFileVersionInfo` + certificate chain check), user_sid,
  integrity_level.
FREQUENCY: real-time (event-driven).
PERFORMANCE NOTE: hashing large files synchronously can lag the event
loop — hash asynchronously in a worker thread pool, don't block the WMI
callback.
FALSE POSITIVE HANDLING: maintain a local allowlist cache (paths of
known-good, previously-seen-and-cleared processes) to avoid re-alerting
every launch of e.g. chrome.exe — but still send the telemetry event
either way (allowlisting affects local_rule_engine severity weighting,
not whether the event exists in telemetry at all — the manager should
always see the ground truth).

--- A7: SERVICE COLLECTOR (collectors/service_collector.py) ---
MECHANISM: WMI __InstanceCreationEvent/__InstanceModificationEvent on
Win32_Service, OR polling `sc query` diff every N seconds as a simpler
fallback (document tradeoff in README).
COLLECTED DATA: service_name, display_name, path_name, start_mode,
state, start_name (account), change_type (created/modified/deleted).
FREQUENCY: event-driven or 30s poll.

--- A8: REGISTRY COLLECTOR (collectors/registry_collector.py) ---
MECHANISM: RegNotifyChangeKeyValue (via ctypes/pywin32) on a curated set
of security-relevant keys — NOT the entire registry (performance).
MONITORED KEYS (at minimum):
  HKLM\Software\Microsoft\Windows\CurrentVersion\Run
  HKCU\Software\Microsoft\Windows\CurrentVersion\Run
  HKLM\System\CurrentControlSet\Services
  HKLM\Software\Microsoft\Windows NT\CurrentVersion\Winlogon
COLLECTED DATA: key_path, value_name, old_value (if available),
new_value, change_type.
FREQUENCY: event-driven.

--- A9: NETWORK COLLECTOR (collectors/network_collector.py) ---
MECHANISM: psutil.net_connections() polled every N seconds (5-10s) for
connection deltas, PLUS optional lightweight packet metadata via scapy
for DNS query logging (do NOT do full packet capture/DPI — scope-appropriate
for a final year project; document this limitation explicitly).
COLLECTED DATA: local_addr, local_port, remote_addr, remote_port,
protocol (TCP/UDP), status, pid, process_name (joined from process
collector's cache), direction (inbound/outbound), dns_query (if captured).
DETECTION-RELEVANT DERIVED SIGNALS (computed here or left to Rule Engine —
document your choice): new listening ports, connections to previously
unseen remote IPs, connection count spike (possible port scan/beaconing).
FREQUENCY: 5-10s poll interval (configurable).

--- A10: USB COLLECTOR (collectors/usb_collector.py) ---
MECHANISM: WMI __InstanceCreationEvent on Win32_USBControllerDevice /
Win32_DiskDrive, or WM_DEVICECHANGE window message hook.
COLLECTED DATA: device_id, device_description, serial_number,
vendor_id, product_id, drive_letter (if mass storage), event_type
(connected/disconnected), file_copy_activity (if feasible — monitor the
new drive letter's directory for a short window post-mount and log
large/bulk file writes; document this as best-effort, not exhaustive DLP).
FREQUENCY: event-driven.

--- A11: FILE COLLECTOR (collectors/file_collector.py) ---
MECHANISM: ReadDirectoryChangesW (via win32file) watching a configurable
set of sensitive directories — NOT the whole filesystem (performance +
noise).
DEFAULT WATCHED PATHS: %APPDATA%, %TEMP%, Desktop, Documents, and any
admin-configured sensitive folders (policy-configurable, pulled from
agent config / a policy push, not hardcoded).
COLLECTED DATA: file_path, change_type (created/modified/deleted/renamed),
file_size, file_hash (for created/modified, small files only —
size-threshold configurable to avoid hashing huge files), process_that_
touched_it (best-effort, joined from process collector if timing allows).
FREQUENCY: event-driven.

--- A12: LOG COLLECTOR (collectors/log_collector.py) ---
MECHANISM: Windows Event Log subscription (win32evtlog /
EvtSubscribe) on Security, System, and Application channels, filtered to
a specific allowlist of Event IDs (not all events — huge noise
otherwise).
KEY EVENT IDS TO WATCH (minimum set):
  4624 (successful logon), 4625 (failed logon), 4648 (explicit credential
  logon), 4672 (special privileges assigned), 4697 (service installed),
  4698 (scheduled task created), 4720 (user account created),
  4732 (user added to security group), 1102 (audit log cleared),
  7045 (new service installed - System log)
COLLECTED DATA: event_id, channel, timestamp, event_data (parsed XML ->
dict of the event-specific fields).
FREQUENCY: event-driven (subscription push).

--- LOGIN COLLECTOR (collectors/login_collector.py — folds into A12 or
separate; keep separate if you want a cleaner "user activity" story) ---
MECHANISM: WTSRegisterSessionNotification (win32ts) for
logon/logoff/lock/unlock session events, complementing the 4624/4625
event log entries with real-time session state (locked vs active).
COLLECTED DATA: session_id, user_sid, event_type (logon/logoff/lock/
unlock/remote_connect/remote_disconnect), timestamp.

SHARED COLLECTOR TESTS (write once, parametrize per collector):

- each collector_type() returns the correct constant used by the manager

MODULE A14: POWERSHELL EXECUTOR
--------------------------------------------------------------------------------
PURPOSE: The ONLY place in the agent that shells out to PowerShell —
tightly controlled, allowlisted, parameterized, never string-concatenated
from untrusted input.

CLASSES & METHODS:

class PowerShellExecutor:
    def __init__(self, scripts_dir: str, timeout_seconds: int = 30): ...
    def execute_template(self, template_name: str,
                           params: dict[str, str]) -> PSResult:
        """template_name must match an allowlisted .ps1 file in
        scripts_dir (raise UnknownTemplateError otherwise — NEVER accept
        arbitrary script content or command strings from a command
        payload). Parameters are passed via PowerShell's own -Param
        mechanism (subprocess argument list, NOT string interpolation
        into a shell command — this is the #1 injection risk to avoid).
        Runs with a timeout; kills the process on timeout and returns a
        PSResult(success=False, error='timeout'). Captures stdout/stderr,
        exit code."""

ALLOWLISTED SCRIPT TEMPLATES (powershell/scripts/*.ps1 — one per
response action, each taking ONLY the specific typed parameters it needs):
  logoff_user.ps1            (param: SessionId or "*" for all sessions)
  kill_process.ps1           (param: ProcessId or ProcessName)
  add_firewall_block_rule.ps1 (params: RuleName, Direction, RemoteIP/Any)
  remove_firewall_rule.ps1   (param: RuleName)
  disable_network_adapter.ps1 (param: AdapterName or "all")
  enable_network_adapter.ps1
  lock_workstation.ps1        (no params — calls rundll32
                                user32.dll,LockWorkStation)
  create_scheduled_task.ps1   (params: TaskName, TriggerType, Action —
                                used cautiously, mainly for scheduled
                                self-checks, not arbitrary task creation)
  delete_scheduled_task.ps1   (param: TaskName)
  stop_service.ps1            (param: ServiceName)
  start_service.ps1           (param: ServiceName)

EXCEPTIONS: UnknownTemplateError, PSExecutionTimeoutError,
PSExecutionFailedError, InvalidParameterError (validate param types/format
before ever building the subprocess call — e.g. ProcessId must be a
positive int, RuleName must match a safe charset regex).

TESTS: attempting to execute a non-allowlisted template raises
UnknownTemplateError; parameters with shell metacharacters
(;, |, &, $, backticks) are rejected by InvalidParameterError BEFORE
subprocess is ever invoked (this is a security-critical test — write
several injection-attempt test cases); timeout is enforced and the
process is actually killed, not just the Python call abandoned (verify no
orphaned process via a test that spawns a deliberately slow ps1 fixture).

MODULE A15: RESPONSE ENGINE
--------------------------------------------------------------------------------
PURPOSE: Receives a verified SignedCommand (already validated by
communication layer per SECTION 4) and maps it to the correct PowerShell
template or native Windows API call.

CLASSES & METHODS:

class ResponseEngine:
    def __init__(self, ps_executor: PowerShellExecutor,
                  result_reporter: Callable): ...
    async def handle_command(self, command: SignedCommand) -> None:
        """Dispatch table: command_type -> handler method. Every handler
        returns a PSResult or equivalent, which is reported back via
        result_reporter (wired to /agent/commands/result). Wraps every
        handler call in try/except -> reports status='failed',
        error=str(exception) on any unhandled exception, so a bad
        response action never crashes the agent process."""
    def _handle_logoff_user(self, params: dict) -> PSResult: ...
    def _handle_kill_process(self, params: dict) -> PSResult:
        """Prefer psutil.Process(pid).terminate()/kill() directly over
        PowerShell for this one — it's simpler and avoids a subprocess
        for something the Python stdlib does natively; document this
        deliberate deviation from 'PowerShell for everything' in the
        README with the reasoning (use the right tool, not PowerShell
        dogma)."""
    def _handle_disable_network(self, params: dict) -> PSResult:
        """Full isolation: disables all adapters except loopback AND
        optionally keeps a narrow allowlisted route to the manager's IP
        so the agent can still receive the RE-ENABLE command later
        (critical design decision — document and implement this
        carefully, a fully isolated agent that can never be un-isolated
        remotely is a real operational problem worth solving in the
        report)."""
    def _handle_disable_adapter(self, params: dict) -> PSResult: ...
    def _handle_lock_workstation(self, params: dict) -> PSResult: ...
    def _handle_firewall_rule(self, params: dict, add: bool) -> PSResult: ...
    def _handle_quarantine_file(self, params: dict) -> PSResult:
        """Moves file to a protected quarantine directory (agent-install-
        dir-local, ACL'd to SYSTEM/admin only) and renames with a
        non-executable extension; records original path for RESTORE_FILE."""
    def _handle_restore_file(self, params: dict) -> PSResult: ...
    def _handle_scheduled_task(self, params: dict, create: bool) -> PSResult: ...
    def _handle_service_control(self, params: dict, start: bool) -> PSResult: ...

TESTS: each handler tested against a mocked ps_executor/psutil (assert
correct template + params passed); an exception inside any handler is
caught and reported as a failed result, never propagates and crashes the
agent; DISABLE_NETWORK isolation preserves a route back to the manager
(test the actual firewall/route rule content produced, not just that a
function was called).

MODULE A16: SELF PROTECTION
--------------------------------------------------------------------------------
PURPOSE: Resist tampering by standard (non-admin) users. Document clearly
(in the README and your final report) that this does NOT claim to resist
a local Administrator — that requires a kernel driver / ELAM, out of scope.

CLASSES & METHODS:

class ServiceGuard:
    def configure_service_acl(self) -> None:
        """Uses `sc.exe sdset` or win32security to set a security
        descriptor on the Windows Service that denies SERVICE_STOP and
        SERVICE_PAUSE_CONTINUE to non-admin SIDs, while allowing
        SERVICE_QUERY_STATUS to everyone (so it's visible but not
        stoppable) — run this once at service install time."""
    def watchdog_loop(self) -> None:
        """A secondary lightweight watchdog (can be a second, differently
        -named scheduled task or a minimal separate service) that checks
        the main service's status every N seconds and restarts it if
        stopped/crashed — mutual restart pattern (each watches the
        other) is a nice touch to mention in your report, but a single
        watchdog is sufficient for FYP scope."""

class FileIntegrityGuard:
    def restrict_install_directory_acl(self, install_dir: str) -> None:
        """Sets NTFS ACLs on the install directory + config files so
        only SYSTEM/Administrators have write access; standard users get
        read+execute only (or no access to config/certs at all)."""
    def verify_integrity(self) -> IntegrityCheckResult:
        """On startup and periodically, hashes critical files (the main
        executable, config.py, key files) and compares against a stored
        manifest (signed/protected itself) — flags tampering."""

class TamperLogger:
    def log_tamper_attempt(self, attempt_type: str, details: dict) -> None:
        """Logs locally (protected log file) AND attempts to send an
        immediate high-priority telemetry event to the manager ('agent
        tamper attempt detected on {hostname}') — this event should
        bypass the normal batching and be sent immediately if online."""

WINDOWS SERVICE RECOVERY CONFIG: use `sc.exe failure` (or the equivalent
win32serviceutil config) to set the service's built-in recovery actions —
restart on 1st/2nd/subsequent failure, with a reset period — this is the
simplest, most defensible "auto-restart on crash" mechanism (native
Windows feature, don't reinvent it).

TESTS: non-admin token (simulate via a restricted test context or
document as a manual Windows integration test since true privilege
testing is hard to fully automate) cannot stop the service; ACL denies
write to install dir for a standard user; integrity check flags a
deliberately modified test file; tamper logger produces a log entry AND
attempts the immediate-send path (mock the transport, assert it was
